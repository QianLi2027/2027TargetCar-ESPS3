# 靶车导轨控制板（ESP32-S3 + 2×M3508）

> 一块 ESP32-S3 开热点、跑网页，直接驱动导轨上的两个 M3508；
> 同时通过 ESP-01S 把「6020 方向 + 挡位」转发给 C 板（靶车主体）。

---

##

```
手机 ──WiFi──► ESP32-S3（本板：热点 TARGET_CAR / 192.168.4.1）
                  │  ├─ CAN 1Mbps ──► M3508 ×2（导轨）
                  │  └─ TCP 3333 ──► ESP-01S ──USART1──► C 板 ──CAN──► GM6020
```

1. **导轨**：两个 M3508 一正一反装在导轨两端，做双速度环；
2. **网页**：开 AP、跑 HTTP + WebSocket，手机连上就能操作；
3. **转发**：把网页选的 6020 方向/挡位，每 100 ms 通过 TCP 发给 C 板

---



## 软件结构

```
main/main.cpp              上电流程
components/
├─ task/                   业务
│   ├─ Horizontal_ctrl/    导轨控制环（1 ms）
│   ├─ Locating/           定零状态机 + 位置/软限位
│   └─ Communication/      与 C 板的 TCP 链路（端口 3333）
├─ device/                 具体外设
│   ├─ CAN/                电机对象、组帧、分发
│   ├─ Led/                WS2812 状态灯
│   └─ Buzzer/             蜂鸣器 + 连接状态提示
├─ bsp/                    TWAI 收发、CAN 字节工具
├─ net/                    WiFi AP / WebSocket / DNS 强制门户 / 网页指令状态
└─ algorithm/              PID
```

| 任务                             | 优先级 | 周期             | 干什么                        |
| ------------------------------ | --- | -------------- | -------------------------- |
| `HorizontalTask`               | 20  | **1 ms**       | 模式状态机 → 软限位 → 双速度环 → 发 CAN |
| `locating`                     | 19  | 1 ms（空闲 50 ms） | 定零：未回零时阻塞顶墙，失败 5 s 重试      |
| `can_rx`                       | 10  | 阻塞接收           | TWAI 收帧 → 分发 → 解码          |
| `rail_link`                    | 5   | 100 ms         | TCP 服务端，给 C 板推方向/挡位        |
| `dns_redirect`                 | 5   | 阻塞             | 强制门户：所有域名解析回本机             |
| `buzzer_play` / `buzzer_watch` | 5   | 事件 / 50 ms     | 播放提示音、监测连接变化               |

FreeRTOS tick = **1000 Hz**

## 定零状态机

位置来自 M3508 增量编码器，没顶过墙就不知道自己在哪，所以只有两个状态：

```
        ┌────────────┐   撞墙成功（≤30 s）   ┌───────────┐
        │ NotLocated │ ───────────────────► │  Located  │
        │  未回零    │ ◄─────────────────── │  已回零   │
        └────────────┘   超时 / 重新定零请求  └───────────┘
```

- **上电**：`Locating_Run()` 阻塞跑一次（在开 WiFi 之前）；
- **之后**：`locating` 任务接管——未回零就阻塞顶墙，失败等 5 s 再来，直到成功；
  已回零时每 50 ms 醒一次，几乎不干活；
- **重新定零**：任何条件调 `Locating_Request()`，状态打回未回零，重跑一轮；
- **未回零时**：控制环一个位移指令都不发（电机归定零任务驱动），网页怎么点都不动；
- **心跳兜底**：控制环发现"未回零 + 定零任务心跳超过 100 ms 没更新"，自己发 0 电流，
  防止任务卡死时电调保持最后一条指令。

| 参数   | 值                                 |
| ---- | --------------------------------- |
| 顶墙速度 | 1200（转子 rpm）                      |
| 单次超时 | 30 s                              |
| 堵转判定 | 转速 < 50 rpm 且 电流 > 3000，连续 400 ms |
| 启动宽限 | 800 ms                            |
| 失败重试 | 5 s                               |
| 总行程  | 4,480,261 计数（撞墙点 → 另一端）           |
| 软限位  | 6% ~ 94%                          |

```
网页/默认模式 → 目标速度 → 软限位 → SpeedPID → 限幅 → CAN 0x200
```

| 参数     | 值               | 说明                      |
| ------ | --------------- | ----------------------- |
| PID    | 5.0 / 1.0 / 0.0 | 输出限幅 ±10000，积分限幅 ±2500  |
| 周期     | 1 ms            | `vTaskDelayUntil`，不累积漂移 |
| 默认模式速度 | 8000            | 在两个位置点之间来回              |
| 往返范围   | 6% ~ 94%        | 每次换向停 0.8 s             |
| 电流限幅   | ±16000          | M3508 满量程 ±16384        |
| 掉线保护   | 800 ms          | 网页没了就停（只对无线控制）          |

**三种模式**（网页上选）：

| mode   | 含义                             |
| ------ | ------------------------------ |
| `0xFF` | 未选择：目标 0                       |
| `0`    | 默认模式：停 0.8 s → 在 6%~94% 之间自动往返 |
| `1`    | 无线控制：听网页的方向和转速                 |

## 网页

- 地址 `http://192.168.4.1`，页面内嵌在固件里，不依赖文件系统；
- WebSocket `/ws`，浏览器每 200 ms 发一条 **4 字段**文本，既是指令也是心跳：
  `"导轨转速,导轨方向,6020方向,6020挡位"`，例 `"3500,STOP,FORWARD,2"`；
  - 导轨方向：`LEFT / STOP / RIGHT`
  - 6020 方向：`FORWARD / STOP / REVERSE`
  - 挡位：`1=25 / 2=45 / 3=90 / 4=120` rpm
- 最多 4 个网页同时连，但同一时刻只有一个持有**控制权**（点"接管控制"）；
- DNS 重定向 + 404 跳首页，手机连上热点会自动弹页面。

## 和 C 板的链路（TCP 3333）

ESP32 是**服务端**，C 板上的 ESP-01S 主动连过来。每 100 ms 推一条：

```
FORWARD,2\n    方向,挡位
IDLE,0\n       保活（网页掉线/没人接管时发，让靶车停住）
```

C 板不回任何数据。协议细节、AT 流程参考 **`ESP-01S通信.md`**。
